# 行知旅行 · 问答助手与 MVP 系统说明

> 对应任务清单 src 部分：1、问答助手归档；2、MVP 项目（工程架构、Agent 框架、知识库、至少 3 处人工确认/审核点）

## 一、问答助手归档（src 第 1 项）

问答助手是 MVP 的一个核心模块，基于知识库检索实现，用于解答行程变更与异常协作相关的业务问题。

### 1.1 能力定位
- 基于 36 条访谈证据（f00–f55）+ 8 条常见问题（FAQ）的知识库
- 支持指标、流程、权限、审核门等类别的问答
- 答案引用证据编号，可追溯来源
- 低置信问题提示转人工，不臆造答案

### 1.2 归档位置
- 代码：`资料/11-MVP系统/index.html`（问答助手 Tab）
- 逻辑：`资料/11-MVP系统/app.js`（searchKB 检索函数）
- 知识库：`资料/11-MVP系统/kb.js`（36 条证据 + FAQ）

## 二、MVP 项目（src 第 2 项）

### 2.1 工程架构（六层）

| 层级 | 职责 | 本期实现 |
|---|---|---|
| 接入层 | 事件源对接 + 人工登记 | 有接口走接口，无接口走人工登记表单 |
| 数据协同层 | 三系统只读接入、主键关联、版本校验 | 团号+订单号+版本号唯一凭据 |
| 规则与计算层 | 变更识别、影响面计算、建议生成 | 建议附原记录，不覆盖原版本 |
| 审核与留痕层 | 五级审核门、转人工四要素、审计日志 | 必填校验 + 审批留痕 |
| 触达层 | 多渠道通知、回执采集、超时升级 | 回执区分已读/资源可用 |
| 治理层 | 权限矩阵、规则版本管理、周度复盘 | 谁能看与谁能拍板分离 |

### 2.2 Agent 框架（问答助手）

| 环节 | 实现 |
|---|---|
| 意图识别 | 关键词匹配 → 分类（指标/流程/权限/审核门） |
| 知识检索 | 在 36 条证据 + FAQ 中检索相关条目 |
| 答案生成 | 引用原文 + 证据编号（f00–f55） |
| 人工兜底 | 低置信问题提示转人工 |

### 2.3 知识库
- 36 条访谈证据（六角色各 6 条：运营经理/导游/协调员/工程师/安全主管/服务商）
- 8 条常见问题 FAQ
- 可扩展接入企业知识库

### 2.4 三处人工确认/审核点

| # | 审核点 | 触发场景 | 对应设计 |
|---|---|---|---|
| 审核点 1 | 授权口径确认 | 变更事件接入前，确认口径与权限已签发 | G1 口径与授权签发 |
| 审核点 2 | 影响面建议人工确认 | AI 计算影响面后，协调员核对建议并确认 | G3 建议发布确认 |
| 审核点 3 | 转人工四要素留痕 | 异常/不可逆动作转人工时，强制填写四要素 | G4 不可逆动作审批 |

## 三、运行方式
1. 用现代浏览器打开 `index.html` 即可运行（纯前端，无后端依赖）
2. 也可部署为静态站点，生成在线访问地址

## 四、范围红线
- 不自主退款、不自主改签、不承诺赔偿
- 旅客资料最小可见、脱敏
- 不可逆动作一律人工审批
