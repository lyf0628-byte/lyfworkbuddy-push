# 行知旅行 · 问答助手与 MVP 系统说明

> 对应任务清单 src 部分：1、问答助手归档；2、MVP 项目（工程架构、Agent 框架、知识库、至少 3 处人工确认/审核点）

## 一、问答助手归档（src 第 1 项）

### 1.1 阶段定位

阶段 1 的目标是回答一个技术问题：**在行知旅行的规程 + 访谈证据这类小语料上，纯前端关键词检索能不能撑住问答？**

结论：能撑住"查指标、查口径、查审核门"，撑不住"登记事件、下发通知、转人工留痕"这类带业务副作用与安全闸门的操作。因此阶段 2 演进为「规则引擎 + Agent + 人工确认闸门」的可运行后端系统。

### 1.2 归档内容（阶段 1 · 纯前端演示）

| 文件 | 说明 |
|---|---|
| `阶段1-前端演示/index.html` | 单页演示（总览/问答/通知闭环/审核台/架构） |
| `阶段1-前端演示/app.js` | 关键词检索逻辑（searchKB） |
| `阶段1-前端演示/kb.js` | 36 条访谈证据 + 8 条 FAQ |

### 1.3 问答助手能力（延续到阶段 2）

- 基于规程 + 访谈证据的知识库检索（阶段 2 升级为 BM25 + 向量 + RRF 混合检索）
- 答案引用来源（条文标题 + 章节）
- 低置信/域外问题明确答"未找到"，不臆造

## 二、MVP 项目（src 第 2 项）

MVP 已从纯前端演示**升级为真实可运行的后端系统**，代码位于 `../src2-MVP系统/`。

### 2.1 工程架构（六层）

| 层 | 模块 | 实现 |
|---|---|---|
| 接入层 | `app/web/` | 登录、员工端 SSE 对话、管理后台 |
| 应用层 | `app/main.py` | FastAPI 应用 |
| Agent 层 | `app/agent/` | 规则引擎 + 六工具 + 5 轮循环 |
| 检索层 | `app/rag/index.py` | BM25 + 向量 + RRF + 门禁 |
| 数据层 | `app/db.py` | SQLite 13 张表 |
| 安全层 | `security.py` `privacy.py` | JWT + 脱敏 |

### 2.2 Agent 框架

- 双脑：`HeuristicBrain`（离线确定性）+ `LLMBrain`（真实 Function Calling）
- 5 轮工具循环，逐轮写 `agent_logs` 审计日志
- 六工具：search_policy / compute_impact / register_event / notify_parties / manual_handoff / list_my_events

### 2.3 知识库

- 混合检索：bigram 分词 + BM25 + 特征哈希向量 + RRF 融合 + 相关性门禁 + 域外弃答
- 语料：`data/policies/` 两份规程文档，切片落库可追溯

### 2.4 三处人工确认/审核点

| # | 审核点 | 触发场景 | 代码闸门 |
|---|---|---|---|
| 1 | G1 口径与授权签发 | 事件接入前确认口径签发 | 规程 + 提示词约束 |
| 2 | G3 建议发布确认 | 通知下发前人工确认影响面 | `confirm_notify` 闸门（未确认返回 GATE_G3_REQUIRED） |
| 3 | G4 不可逆动作审批 | 退款/改签/赔偿转人工 | `is_irreversible` + 四要素强制留痕 |

## 三、运行方式

```bash
cd ../src2-MVP系统
python quickstart.py          # 控制台 3 场景（零依赖）
python evals/run_eval.py      # 30 条评测（30/30）
python run.py --port 8000     # Web 版
```

## 四、范围红线

- 不自主退款、不自主改签、不承诺赔偿
- 旅客资料最小可见、脱敏
- 不可逆动作一律人工审批（G4）
