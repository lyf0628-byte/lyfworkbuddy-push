# 行知旅行行程变更协作规程

> 版本 V1.0 ｜ 生效日期 2026-11-06 ｜ 编制：运营经理 顾明岚

本规程是「行程变更与异常协作」系统的业务口径与权限基线，所有智能判断与人工审核均以此为准。

## 一、核心量化指标

| 指标 | 当前基线 | 目标值 |
|---|---|---|
| 行程变更通知遗漏率 | 14% | 2% |
| 异常确认平均耗时 | 80 分钟 | 20 分钟 |
| 关键变更覆盖率 | — | 100% |

## 二、完成口径（P0-①）

- 变更闭环的完成判定以「确认回执」为准，而非「通知发出」。
- 回执区分两类：**已读**（对方已看到）与**资源可用**（对方确认可执行）。
- 只有「资源可用」回执才算闭环完成；仅「已读」属中间态，不计入完成。

## 三、转人工四要素（P0-②）

异常或不可逆动作转人工时，必须强制记录四项要素，缺一不可：

1. 触发原因
2. 接手人
3. 确认时间
4. 业务编号 + 资料版本

仅给模糊提醒（如「已转交」）不予验收。

## 四、授权口径（P1-③）

- 「谁能看」与「谁能拍板」分离。
- 旅客名单仅相关角色可见，最小可见 + 脱敏。
- 哪些异常必须转人工、谁能拍板、否决权归属，由运营经理出具成文清单。

## 五、主键与版本（P1-④）

- 三系统（CRM / 行程表 / 供应商消息平台）主键统一为「团号 + 订单号 + 版本号」。
- 有歧义记录进入人工修复队列，不进入自动推荐样本。

## 六、五道审核门（G1-G5）

| 审核门 | 名称 | 责任方 |
|---|---|---|
| G1 | 口径与授权签发 | 运营经理 |
| G2 | 数据与主键校验 | 平台工程师 |
| G3 | 建议发布确认 | 行程协调员 |
| G4 | 不可逆动作审批 | 授权审批人 / 安全主管 |
| G5 | 试点放行与复盘 | 运营经理 + 安全主管 |

## 七、不可逆动作红线（G4）

以下动作系统不得自主执行，一律强制人工审批：

- 退款、改签、赔偿
- 发车、入住、接待、对外承诺
- 资产变更、旅客资料访问

## 八、留存与审计（P2-⑦）

- 全链路留痕：业务编号、资料版本、事实引用、建议结果、人工改动、签核人。
- 评价记录暂保留 90 天，期满由安全主管复核删除或归档。
- 不记录账号口令与不必要个人信息。
